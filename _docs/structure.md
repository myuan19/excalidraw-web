# 文档结构说明

## 一、总体原则

`docs/` 以版本目录为主要组织方式。每个版本创建一个独立目录，例如 `v0.1.0/`、`v0.2.0/`。

版本目录用于沉淀该版本相关的业务现状、设计方案、变更说明和功能文档。版本无关的工具产物、执行计划、原始材料可以放在独立目录中，不强制归入版本目录。

## 二、版本目录结构

每个版本目录默认包含以下两类子目录：

- `当前情况/`：记录该版本开始或维护时的现状，包括已有功能、系统状态、问题背景、约束条件和调研结论。
- `新增功能/`：记录该版本计划新增或已经新增的功能，包括技术方案、功能设计、实施说明、验收标准和相关决策。

示例：

```text
docs/
  v0.1.0/
    当前情况/
    新增功能/
```

## 三、允许的独立目录

除了版本目录以外，`docs/` 允许保留面向特定用途的独立目录。

- `superpowers/`：存放 Superpowers 工作流生成的设计、计划、执行记录等辅助产物。
- `raw/`：存放原始材料、临时记录、待整理对话和未结构化资料。

后续如果出现新的长期用途目录，可以在本文件中补充说明。

## 四、命名约定

- 版本目录使用 `vX.Y.Z` 格式。
- 普通文档默认使用中文文件名。
- 文件名不包含空格；英文单词之间使用连字符。
- 版本相关文档优先放入对应版本目录下的 `当前情况/` 或 `新增功能/`。

## 五、维护约定

- 新建、移动、合并、删除文档后更新 `log.md`。
- 普通文档必须包含完整 front matter。
- `structure.md` 和 `log.md` 只保留最小 front matter。
- 当文档同时涉及版本内容和工具执行过程时，版本结论放入版本目录，执行计划或过程记录可以保留在 `superpowers/`。
