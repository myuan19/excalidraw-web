# 调用保存文档功能

## 核心 API

所有保存操作统一通过 `app/data/saveQueue.ts` 提供的两个函数发起：

```ts
import { requestSave } from "app/data/saveQueue";
import { requestSaveAndWait } from "app/data/saveQueue";
```

### `requestSave(req)` — 发起保存（fire-and-forget）

```ts
requestSave({ source: "sidebar" });
requestSave({ source: "auto" });
requestSave({ source: "visibility" });
```

调用后立即返回，不等待保存完成。适用于绝大多数场景。

### `requestSaveAndWait(req)` — 发起保存并等待结果

```ts
const result = await requestSaveAndWait({
  source: "home",
  navigateAfter: true,
});
// result.saved === true 表示保存成功
```

返回 Promise，保存完成后 resolve。适用于需要先保存再执行后续操作的场景（如保存后跳转首页）。

## SaveRequest 参数

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `source` | `SaveToServerSource` | **必填**。标识触发来源，影响合并优先级和 UI 提示 |
| `navigateAfter` | `boolean` | 保存完成后是否跳转到首页 |
| `forceThumbnail` | `boolean` | 强制重新生成缩略图 |

### source 取值

| 值             | 含义             | 优先级 | 执行方式       |
| -------------- | ---------------- | ------ | -------------- |
| `"toolbar"`    | 工具栏按钮       | 高     | 立即           |
| `"hotkey"`     | 快捷键 Ctrl+S    | 高     | 立即           |
| `"sidebar"`    | 悬浮球保存按钮   | 高     | 立即           |
| `"home"`       | 返回首页前保存   | 高     | 立即           |
| `"visibility"` | 切换到后台时触发 | 中     | 300ms 合并窗口 |
| `"auto"`       | 空闲自动保存     | 低     | 300ms 合并窗口 |

## 调用后发生了什么

1. **合并**：300ms 内多次调用会合并为一次保存，保留优先级最高的 source
2. **排队**：如果上一次保存尚未完成，新请求排队等待，不会并发执行
3. **执行**：调用编辑器注册的 executor 完成实际保存（数据上传、hash 同步等）
4. **后处理**：保存成功后自动执行跨 tab 广播和自动存档管理，调用方无需关心

## 典型用法

**新增一个保存触发点**（如定时器、快捷键、按钮）：

```ts
import { requestSave } from "app/data/saveQueue";

// 只需一行
requestSave({ source: "toolbar" });
```

**需要等待保存完成再做其他事**（如保存后跳转）：

```ts
import { requestSaveAndWait } from "app/data/saveQueue";

await requestSaveAndWait({ source: "home", navigateAfter: true });
```

不需要关心保存的具体实现、并发控制、跨 tab 同步或存档管理——队列全部处理。
