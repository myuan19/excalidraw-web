# 画布位置持久化实现对比（MindMap vs Excalidraw）

> 两者本质相同：监听视图变化 → 序列化到 localStorage → 加载时反序列化恢复。差异在于数据模型、存储粒度和恢复策略。

## 一、核心差异总览

| 方面 | MindMap | Excalidraw |
| --- | --- | --- |
| 存储位置 | localStorage 单一 key | localStorage per-file key |
| 保存触发 | `view_data_change` 事件 + 300ms 防抖 | `onChange` 回调 + 300ms debounce |
| 保存内容 | SVG transform 矩阵 + 内部状态 (scale, x, y) | appState 中的 scrollX, scrollY, zoom 等 |
| 数据结构 | 独立 `view` 字段 | appState 的子集（配置表过滤） |
| 恢复方式 | 构造函数参数 `viewData` 直接设置 | `initialData` 中 merge appState overlay |
| 多文件支持 | 单文件，全局一个 key | 每个文件独立 key（`fork-browser-scene-v1-{fileId}`） |
| 首次无数据 | 使用默认位置 | `scrollToContent: true` 自动适配 |

## 二、MindMap 的实现

### 2.1 保存链路

视图变换时，`View.transform()` 触发 `view_data_change` 事件：

```
// simple-mind-map/src/core/view/View.js
transform() {
  this.mindMap.draw.transform({
    origin: [0, 0],
    scale: this.scale,
    translate: [this.x, this.y]
  })
  this.mindMap.emit('view_data_change', this.getTransformData())
}
```

`Edit.vue` 监听该事件，300ms 防抖后调用 `storeData`：

```
// web/src/pages/Edit/components/Edit.vue
this.$bus.$on('view_data_change', data => {
  clearTimeout(this.storeConfigTimer)
  this.storeConfigTimer = setTimeout(() => {
    storeData({ view: data })
  }, 300)
})
```

`storeData` 合并后写入 localStorage，key 为 `SIMPLE_MIND_MAP_DATA`：

```
// web/src/api/index.js
localStorage.setItem(SIMPLE_MIND_MAP_DATA, JSON.stringify(originData))
```

### 2.2 保存的数据结构

```
{
  transform: { scaleX, scaleY, translateX, translateY, ... },  // SVG draw.transform()
  state: { scale, x, y, sx, sy }                                // 内部视图状态
}
```

### 2.3 恢复链路

1. `getData()` 从 localStorage 读取完整数据（含 `view` 字段）
2. `init()` 将 `view` 作为 `viewData` 传给 MindMap 构造函数（`fit: false` 避免覆盖）
3. `View` 构造函数调用 `setTransformData(viewData)` 恢复位置

```
// simple-mind-map/src/core/view/View.js
setTransformData(viewData) {
  if (viewData) {
    Object.keys(viewData.state).forEach(prop => {
      this[prop] = viewData.state[prop]
    })
    this.mindMap.draw.transform({ ...viewData.transform })
  }
}
```

### 2.4 关键文件

| 文件 | 职责 |
| --- | --- |
| `simple-mind-map/src/core/view/View.js` | 视图状态管理：平移/缩放/序列化/反序列化 |
| `web/src/pages/Edit/components/Edit.vue` | 事件监听 + 保存调度 |
| `web/src/api/index.js` | localStorage 读写（`getData` / `storeData`） |

## 三、Excalidraw 的实现

### 3.1 保存链路

Excalidraw 组件的 `onChange` 回调在每次状态变化时触发：

```
// excalidraw-app/EditorShell.tsx
const onChange = (elements, appState, files) => {
  if (!document.hidden) {
    LocalData.save(elements, appState, files, onFilesSaved, getFileIdFromHash());
  }
}
```

`LocalData.save` 内部调用 `saveForkBrowserScene`，将 appState 过滤后存入 localStorage：

```
// excalidraw-app/data/forkBrowserSceneStorage.ts
export function saveForkBrowserScene(fileId, elements, appState) {
  const payload = {
    v: 1,
    elements: getNonDeletedElements(elements),
    appState: clearAppStateForLocalStorage(appState),
  };
  localStorage.setItem(`fork-browser-scene-v1-${fileId}`, JSON.stringify(payload));
}
```

### 3.2 哪些字段被持久化

`clearAppStateForLocalStorage` 根据 `APP_STATE_STORAGE_CONF` 配置表过滤，视口相关字段均标记为 `browser: true`：

```
// packages/excalidraw/appState.ts
scrollX:       { browser: true, export: false, server: false }
scrollY:       { browser: true, export: false, server: false }
zoom:          { browser: true, export: false, server: false }
scrolledOutside: { browser: true, export: false, server: false }
```

### 3.3 恢复链路

1. `initializeScene` 从 localStorage 读取浏览器端 appState overlay：

```
const forkBrowserOverlay = readForkBrowserAppStateOverlay(fileIdFromHash);
```

2. `readForkBrowserAppStateOverlay` 解析 localStorage 中的 `fork-browser-scene-v1-{fileId}`，通过 `restoreAppState` 恢复

3. `buildInitResult` 将 overlay 合并到初始数据：

```
function buildInitResult(data, overlay) {
  return {
    scene: {
      elements: restoreSceneElements(data.elements),
      appState: restoreSceneAppState(data.appState, overlay),
      ...(overlay ? {} : { scrollToContent: true }),  // 无 overlay 时自动适配
    },
    hasBrowserViewport: !!overlay,
  };
}
```

### 3.4 关键文件

| 文件 | 职责 |
| --- | --- |
| `packages/excalidraw/appState.ts` | 定义 `APP_STATE_STORAGE_CONF`，控制哪些字段持久化 |
| `excalidraw-app/data/forkBrowserSceneStorage.ts` | per-file 浏览器视口快照的读写 |
| `excalidraw-app/data/sceneRestore.ts` | 场景 appState/elements 的恢复管线 |
| `excalidraw-app/EditorShell.tsx` | `onChange` → 保存，`initializeScene` → 恢复 |
| `excalidraw-app/data/LocalData.ts` | 保存调度入口（debounce + IndexedDB 图片） |

## 四、设计差异分析

### 4.1 数据模型

MindMap 将视口作为**独立的 `view` 字段**与文档数据（`root`、`theme`、`layout`）并列存储，关注点分离清晰。

Excalidraw 将 `scrollX`/`scrollY`/`zoom` 作为 **`appState` 的一部分**，通过统一的配置表 `APP_STATE_STORAGE_CONF` 控制每个字段在不同存储目标（browser/export/server）的去留。这种方式扩展性更强，新增字段只需在配置表中声明。

### 4.2 存储粒度

MindMap 使用全局单一 key `SIMPLE_MIND_MAP_DATA`，所有数据（节点树、主题、视口）合并在一个 JSON 中。简单但不支持多文件。

Excalidraw 使用 per-file key `fork-browser-scene-v1-{fileId}`，多文件切换时各自独立。但依赖 URL hash 中的 `#file=` 才会触发持久化；无 fileId 时不保存视口。

### 4.3 首次加载策略

MindMap 首次无 `view` 数据时使用默认位置（scale=1, x=0, y=0），不做自动适配。

Excalidraw 首次无 overlay 时设 `scrollToContent: true`，自动将画布滚动到内容中心。
